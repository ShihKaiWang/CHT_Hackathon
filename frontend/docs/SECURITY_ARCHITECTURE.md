## 各層詳細說明

### 第 1 層：AWS 基礎設施（部署後生效）

| 服務 | 防護內容 | 費用 |
|------|---------|------|
| CloudFront | 全球邊緣節點分散流量，源站不直接暴露 | 含在內 |
| AWS Shield Standard | 自動防護 L3/L4 DDoS（SYN flood、UDP flood） | 免費 |
| AWS WAF | 自訂規則封鎖惡意 IP/國家/請求模式 | ~$5/月 |
| ECS Auto Scaling | 流量激增時自動擴容 | 按需 |

### 第 2 層：連線層防護（已實作）

| 機制 | 設定 | 行為 |
|------|------|------|
| Rate Limiting | 60 req/min per IP | 超過 → 429 |
| IP 自動黑名單 | 10 次 429 → 封鎖 5 分鐘 | 封鎖 → 403 |
| 手動封鎖 | 指揮官可手動 block IP | 永久/暫時 |
| 請求超時 | 30 秒 | 超時 → 504 |
| Body Size | 1MB 上限 | 超過 → 413 |

### 第 3 層：身份認證（已實作）

| 機制 | 說明 |
|------|------|
| JWT Token | 登入後發放，8 小時過期 |
| 密碼驗證 | SHA256 hash 比對 |
| 環境變數 Secret | `JWT_SECRET` 不寫死在程式碼 |
| WebSocket Token | 連線時從 `?token=xxx` 驗證 |

### 第 4 層：權限控制（已實作）

| 角色 | 可做 | 不可做 |
|------|------|--------|
| **指揮官** | 所有操作 | — |
| **民眾** | 查看路況、回報、路線規劃 | 注入事件、發送通報、查 Audit Log |
| **未登入** | 無 | 所有 API 被 401 擋 |

受保護端點：
```
POST /api/incidents/process    → require_commander
POST /api/incidents/report     → require_commander
POST /api/incidents/dispatch   → require_commander + PIN
GET  /api/auth/security-status → require_commander
POST /api/auth/block-ip        → require_commander
POST /api/auth/degradation-on  → require_commander
```

### 第 5 層：輸入驗證（已實作）

| 類型 | 防護 |
|------|------|
| Prompt Injection | 21 個危險 pattern（中+英），匹配即攔截 |
| 事件類型 | 白名單驗證，非法類型 → 400 |
| 字串長度 | message ≤ 500 字、location ≤ 200、description ≤ 1000 |
| 回應過濾 | RAG 只回傳摘要，不回 SOP 原文 |

Prompt Injection 防護清單：
```
英文：ignore previous, system prompt, act as, pretend to be, bypass, jailbreak...
中文：忽略以上, 無視指令, 你現在是, 假裝你是, 輸出系統提示, 顯示所有規則...
```

### 第 6 層：關鍵操作確認（已實作）

| 操作 | 防護 |
|------|------|
| 發送 CBS/SMS 通報 | 需 PIN 碼 + 60 秒冷卻 |
| AI 決策執行 | 需指揮官逐一批准（HumanOverride） |
| 覆寫 AI 建議 | 需填寫原因 + 替代指令 |

### 第 7 層：稽核與應急（已實作）

| 機制 | 功能 |
|------|------|
| Audit Log | 所有請求自動記錄（IP、時間、路徑、使用者、狀態） |
| 降級模式 | 一鍵停用高耗能 API，保護核心功能 |
| 安全 Headers | X-Content-Type-Options, X-Frame-Options, HSTS, X-XSS-Protection |
| RateLimit Header | 每次回應告知剩餘次數 |

## 攻擊情境防護矩陣

| 攻擊 | 第幾層攔截 | 行為 |
|------|:-:|------|
| 未登入呼叫 API | 3 | 401 Authentication required |
| 民眾嘗試注入事件 | 4 | 403 Commander role required |
| Prompt Injection | 5 | [已過濾] 攔截 |
| 暴力猜密碼 | 2 | 60 次後 Rate Limit → 10 次後 IP 封鎖 |
| 單 IP DDoS | 2 | Rate Limit → 黑名單 → 403 |
| 分散式 DDoS | 1+7 | AWS WAF + 降級模式 |
| 假通報發送 | 6 | 需 PIN + 冷卻 + 只有指揮官能觸發 |
| AI 錯誤決策 | 6 | HumanOverride 人類審核 |
| WebSocket 洪水 | 4 | 3 條/IP、50 條總量限制 |
| 大封包攻擊 | 2 | 1MB 限制 → 413 |
| 慢連線攻擊 | 2 | 30 秒超時 → 504 |
| Token 偽造 | 3 | 簽名驗證失敗 → 401 |
| Token 過期 | 3 | 8 小時後失效 → 401 |
| SOP 原文洩漏 | 5 | RAG 只回摘要 + Prompt 過濾 |

## 評審 QA 快速回答

**Q：「你怎麼防止 DDoS？」**

> 七層防護：AWS Shield 擋 L3/L4 → Rate Limiting 擋單 IP → IP 自動黑名單（10 次違規封 5 分鐘）→ WebSocket 連線池（3/IP、50 總量）→ 降級模式一鍵停用高耗能 API。

**Q：「如果有人嘗試發假警報？」**

> 四道關卡：認證（需指揮官 token）→ PIN 二次驗證 → 60 秒冷卻不可連發 → Audit Log 完整記錄可追溯。

**Q：「AI 回答會不會洩漏 SOP？」**

> 有 Prompt Injection 過濾（21 個中英文 pattern），加上 RAG 只回傳相關摘要不回原文。嘗試注入指令會被攔截並記入 Audit Log。

**Q：「民眾能不能偷看指揮官的資料？」**

> 不行。角色分級嚴格隔離——民眾 token 呼叫任何指揮官端點都會被 403 拒絕。
